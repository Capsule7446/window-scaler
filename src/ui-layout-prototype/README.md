# 批量窗口布局原型

**PROTOTYPE：用于选择布局，使用模拟数据，不操作真实窗口。**

问题：以批量管理多个窗口为主时，列表、选择反馈和四个操作入口应该怎样排布？

在当前 worktree 根目录运行：

```powershell
python src/ui-layout-prototype/serve.py
```

打开 `http://127.0.0.1:8876/?variant=A`。底部切换栏或左右方向键可比较：

| 方案 | 排布 | 侧重点 |
| --- | --- | --- |
| A 紧凑列表 | 表格、底部固定操作栏 | 同屏窗口数量与快速批量操作 |
| B 双栏操作台 | 左侧列表、右侧选择与操作面板 | 操作范围清楚，宽度与可见性分区 |
| C 按程序分组 | 按程序组织的卡片、顶部操作栏 | 同一程序多个窗口的定位与选择 |

搜索、勾选、清空、刷新、宽度、缩放、隐藏/显示、正常退出及失败重试均使用内存模拟。原型增加“选择当前列表”和“选择本组”用于评估批量选择体验；是否纳入正式实现随布局方案一起确认。关闭主界面按钮演示收起到托盘。数据可随时重置。

“紧凑尺寸”比较 760×540 与默认预览大小；“模拟部分失败”让下一批操作的一个目标返回失败，以检查结果反馈。下方“查看模拟状态”展示完整相关状态。切换布局保留当前内存状态，刷新浏览器重置数据。

当前行为基线：`e2076ba` 的 `docs/spec.md` 与 `GLOSSARY.md`。跟踪任务：[#21](https://github.com/Capsule7446/window-scaler/issues/21)。原型只保存在 `prototype/21-batch-layouts` 分支；用户选定后，在正式界面重新实现相应布局。

用户于 2026-11-08 选择 **B 双栏操作台**。正式实现保留左侧搜索与窗口列表、右侧选择摘要与分区操作，并纳入“全选当前列表”；使用现有原生窗口操作接口，不引入浏览器运行时。
