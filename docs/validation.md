# 验证记录

## #12 原尺寸回退修复（2026-11-08）

- 确认旧实现只检查 `IsZoomed` 和非零内容区；真实游戏和专用 Win32 窗口均可报告最大化而保持小尺寸。旧回归检查因此失败。
- 修复后发送目标标题栏使用的系统命令并检查实际几何；未实际变大时恢复本次第一次缩小前的内容区。没有记录、工作区不足及恢复失败均保留错误。
- 16 项默认测试、Clippy 通过；覆盖重复最大化、自定义最大尺寸、最大化后最小化、退出回退、无历史记录及回退失败。新增检查证明仅预校验失败时不能固定旧基线；修改前恢复错误尺寸，修改后恢复首次真正缩小前的尺寸。
- 显式指定 4 个 `LaTaleClient_x64.exe` PID 的独立实机测试通过：19356、68120、74948、77336；同一 HWND 内容区均为 `1280×720 → 240×135 → 1280×720`，退出结果均为 `RestoredOriginal`。
- 旧进程没有持久化原尺寸，所以先指定 `1280×720` 恢复可用大小，再由新后端记录并验证回退；这不是找回历史尺寸。实机用例默认忽略，只有明确设置 `WINDOW_SCALER_GAME_PIDS` 并显式执行 ignored 用例才会操作游戏。

## #3 桌面验收

`tests/desktop` 在独立子进程中运行实际 GPUI Application、主窗口、系统托盘与两个外部 Win32 测试窗口，不使用 TestAppContext。输入控件及业务处理器通过 GPUI 调用，关闭和托盘操作通过真实原生窗口消息驱动；不宣称已经逐个物理点击或完成截图验收。

| 场景 | 实际验证 |
| --- | --- |
| normal | 搜索保留两个已选目标、隐藏数量为 1，两个实际内容区均缩为 240 宽；清空勾选后，关闭隐藏主界面；Shell 已注册托盘图标，左键释放回调恢复主界面；真实菜单 Exit 命令退出前最大化两个窗口 |
| busy-retry | 目标线程阻塞 5.5 秒；退出先等待当前批次，超时显示失败且主窗口存活；等待旧请求完成后重试，两个窗口放大后退出 |
| force | 一个窗口拒绝最大化并拒绝恢复尺寸；显示退出错误，另一个成功；明确仍然退出可关闭应用 |
| no-tray | 仅在测试可执行文件中注入托盘创建失败；关闭按钮不能隐藏主界面，备用退出处理器有效 |
| closed | 实际销毁一个已选 HWND；该目标报已关闭，另一个仍成功；刷新移除失效选择，退出跳过关闭窗口 |

这五个场景的测试设置写入临时文件，专用窗口由拥有它们的子进程创建与清理。测试钩子仅在 `cfg(test)` 中存在，发布 EXE 不含钩子。

## 构建与环境

Windows 11 x64，Rust 1.98.0 MSVC、Visual Studio Build Tools 2022。默认测试在 Debug 与 Release 中均通过；格式检查、全部目标及 feature 的 Clippy（警告视为错误）、12 项 CI 规则测试通过。发布工作流另执行静态 MSVC 运行库构建并生成四个附件，候选构建和正式发布分开。

本机只有主屏 `DISPLAY1`：1920×1080，工作区 1920×1032，96 DPI（100%）。只读检查发现 `EnableLUA=0`；降低一次性测试进程的令牌完整性后没有得到预期的 SetProp 拒绝，因此没有把该实验计为权限不足通过，也没有修改 UAC。

## #4 尚未覆盖

- 真实多显示器、跨屏不同 DPI 的尺寸、位置和画面效果；当前没有对应硬件环境。
- UAC/UIPI 生效环境中的真实权限拒绝；专用拒绝窗口和超时测试不能替代它。
- 正式发布前核对最终候选包及版本附件；以上环境验收未完成时保持 Release Issue 打开。

构建成功、模拟条件与实机证据分别记录，不把未执行条件标成通过。后续结果统一更新 [版本验收 #4](https://github.com/Capsule7446/window-scaler/issues/4)。
